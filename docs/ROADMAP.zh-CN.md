# 逐步开发路线：以真实交付为主线

[English](ROADMAP.md) · [设计](DESIGN.md) · [真实修复规范](REPOSITORY_REPAIR.md)

目标是建立长期有用、足够困难的评测，检验智能体能否在信息不完整时完成有实际价值的工作。
真实验收结果决定开发方向；研究对照用于解释失败，不能不断推迟实际应用。

## 质疑、删除、简化

执行 **质疑需求 → 删除 → 简化和优化 → 加速 → 自动化**。
新增机制必须说明服务什么成果、怎样验收、何时删除。
在可控范围内先作决定、执行、保留失败，再根据事实修正。

| 被质疑的要求 | 决定 |
|---|---|
| 扩大合成目录就能获得长期难度 | 停止作为主线扩展；旧版本保留为对照 |
| 先完成历史压缩和更多合成验收，才能做真实任务 | 删除这个依赖，现在接入真实代码交付 |
| 真实修复需要完整 shell、新调度器和新框架 | 七个受限动作，复用采集与证据路径 |
| 退出码为零就是修好 | 环境外部比较行为，不接受自报 PASS |
| 上游正确补丁是公平的智能体基线 | 只作为产物验收对照 |
| 一个公开缺陷能证明高难度和模型区分度 | 首例打通执行，下一阶段建设高难真实题集 |
| 证据不完备就不能作判断 | 选择可修改的实现，运行并依据事实迭代 |

## 当前路线

```text
R0：真实缺陷 → 隔离执行 → 回归验收 → 交付补丁
  → R1：跨文件约束、兼容性与失败恢复组成的高难真实任务
  → R2：强模型交付与实际人工复核成本
  → R3：扩展有用任务，优化已测量的瓶颈
```

旧 P0–P5 顺序不再作为开发依赖。合成任务和机制研究继续保留，已发布结果不改写。
对未来工作的预测效度可以继续研究，但不妨碍现在执行和评分真实工作。

### R0：完成第一个真实交付闭环

2.7 已实现：固定 packaging 修复前源码，检索／阅读／修改动作，新容器执行，
118 项行为验收，版本绑定的验证，主动交付，源码补丁与证据，复用同一采集器。
[六项固定对照](../studies/repository-repair-v1/README.md)检查边界，并用新容器重新执行。

通过标准：上游修复成功；不改源码、只修报告样例、篡改测试、验证后再修改、
空进程成功退出都不能交付。保留完整矩阵、镜像、源码身份和复核差异。
本地响应夹具不能替代真实执行。

删除不服务于真实执行、相关行为验收或保留失败的基础设施。
本步不做自动重试、插件注册、数据库或模型排名。

### R1：建立困难且有用的真实任务

**下一开发阶段：增加三个独立来源的真实缺陷**，涉及跨文件行为或互相作用的兼容性要求。
每项固定修复前状态，说明具体用户损失，定义可执行验收，
保留被接受的上游修复作产物对照，并构造看似合理、却破坏相关行为的部分修复。

模型尝试前固定选题和预算。用现有 Sol、GLM 配置和实用工具执行同一批任务，
保留全部尝试及接入／执行失败。根据实际失败决定下一项改进。

通过标准：交付真实补丁、保护相关行为，实测强模型的区分度与带工具基线是否饱和。
全部轻松通过时保留为回归参照并选择更难的实际工作；
全部因工具失败时先修工具，不能宣称题目难倒模型。

删除仅依赖冷僻格式、缺失依赖、长输入或禁用实用工具制造的难度。
公开历史修复是开发材料，后续留出独立来源；已看过的任务不能改名充当留出集。

### R2：衡量实际委托价值

在未见任务上验收补丁，记录复核时间、返工要求和无需人工修改的完成情况。
采集前确定归属、验收规则与实际可用的对照方法，比较交付成果和总成本。

通过标准：独立任务数量足以支持事先确定的实际决策，同时展示错误和不确定性。
预期价值不存在时发布负结果并收窄用途。合成得分相关性可帮助诊断；
实际交付是主要测量。没有测量人工时间，就不能用模拟步骤数替代。

### R3：扩展有效部分

测量模型输入、执行和复核成本，先删除重复工作，再优化，确有需要才加入调度和持续评估。
模型变强时提高题集难度，保留固定参照；优化不破坏源码／镜像绑定，不隐藏失败。

## 承接的证据

[深度试跑](../studies/coverage-depth-v1/README.md)保留两条直接模式超时与两条带工具成功；
固定脚本可完成全部 24 个合格实例。这支持调整主线，不等于证明模型没有能力。
