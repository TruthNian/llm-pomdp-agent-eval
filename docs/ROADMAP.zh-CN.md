# 逐步开发路线：先质疑、删除，再简化和优化

[完整路线与验收表](ROADMAP.md) · [设计依据](DESIGN.md) · [采集与续跑规范](COLLECTION.md)

长期目标：评估智能体能否在信息不完整、行动消耗资源、问题逐步展开的情况下，交付真正通过验收的结果。模型名称和参数规模是研究变量，项目需要持续积累的是可靠的测量方法与证据。

**持续要求：难度必须高、可以持续提高，并有实测区分度。** 不能让已经被强模型轻易解完的简单任务定义项目上限。
保留版本固定的参照档位，同时按[难度维护规范](DIFFICULTY.md)检查可解性、较强基线、模型天花板与地板效应。

## 五步工作法怎样落实

1. **质疑需求。** 每项功能先回答：它支持什么判断？已有的最小方案为什么不够？什么证据会推翻这项需求？
2. **删除不必要的部分。** 删除重复实现、没有效度依据的承诺和不产生新信息的扩展。保留历史数据、失败记录和必要约束。
3. **简化和优化。** 建立一条可验证的执行路径；先减少状态、分支和隐含默认值，再增加可维护的能力。
4. **缩短反馈周期。** 先跑能揭示错误的小实验；度量实际瓶颈后再优化速度。
5. **自动化。** 只自动化已经证明有价值且语义稳定的流程。

前 3 步是每次开发的入口条件。新增代码行数、场景数量和调用规模都不作为完成指标。

## 本轮已完成的取舍

| 原假设或做法 | 处理 |
|---|---|
| 增加场景名称就能扩大能力覆盖 | 暂停；换皮不算新任务结构 |
| 一段综合提示带来提升，就解释了内在能力 | 收窄结论；只称为对该提示干预的敏感性 |
| 实验中断后重新跑一遍即可 | 替换；保留已完成结果，把中断尝试计为失败，只继续未开始的样本 |
| 多处重复校验能提高可靠性 | 合并；套件定义、证据校验、汇总生成各保留一个实现 |
| 软件升级后可以接着收集同一实验 | 拒绝；续跑要求源文件、Python、平台和版本一致 |
| 现在需要并发、自动重试、插件系统、仪表盘 | 延后；有明确瓶颈或第二个独立实现后再论证 |
| 必须提供单一“自主性总分” | 不引入；先保留成功率、成本、错误类型与干预敏感性 |
| 严格解析就是要求所有服务重复同一种字段布局 | 删除偶然格式要求；保留输出项归属、完整结束、单一动作和工具隔离 |
| 调用本机 GPT 必须开启全局会话共享 | 删除该依赖；只在当前客户端的已授权请求中携带登录凭据 |
| 必须先写随机生成器、调用模型，才能检验新任务 | 删除该依赖；先用固定公开实例完成发现与恢复的四组消融对照 |
| 负对照失败就证明测到了目标能力 | 增加可证伪要求；移除对应障碍后，相关失败策略必须恢复成功 |

## 阶段 0：最小有效测量内核——2.0 已交付

保留公开观察边界、不依赖抽样答案的可解预算、状态版本校验、显式交付、正负对照、轨迹重放和历史冻结。

现有诊断任务的假设集合是公开的，因此暂不宣称测量了未知假设发现、真实软件工程能力或真实工作的预测效度。

## 阶段 1：可靠采集与证据保全——2.1 已实现

[验收记录](../studies/framework-v21-validation/README.md)包含 52 项测试、跨平台 CI，以及 GPT-5.6 Sol / GLM-5.3 的四条真实接入试跑。一次接入桥超时已保留，没有重跑替换。

开发顺序：冻结执行计划 → 保存请求边界 → 保留中断失败 → 只续跑未开始样本 → 核对完整矩阵 → 生成汇总。

- `prepare`：检查配置并冻结任务、模型、条件、重复次数、预算和顺序，不调用模型。
- `status`：查看已完成、中断待归档和尚未开始的样本数。
- `resume`：复核已有证据后继续；已完成的成功或失败都不会重跑。
- 检查点保留最近已落盘的公开行动与观察；请求中的未知用量保持未知。
- 开始记录、结果回执与哈希绑定实验；拒绝篡改、缺失的已提交结果和版本混用。
- 操作系统锁防止两个采集进程竞争；进程崩溃后锁自动释放。

验收：进程强制退出、请求中断、终态提交中断、磁盘写入失败、并发续跑、源文件漂移、轨迹篡改、失败不重试等测试；完整测试集、历史数据核验、离线演示重放及跨平台 CI。真实模型小样本用于验证接入和流程，不能直接形成模型排名。

### 阶段 1.7：删除动作通道中不必要的运行时

**2.3 已实现，离线验收通过；本机多轮接入验收未通过。** [独立验证记录](../studies/direct-channel-validation-v1/README.md)将完整 Codex 运行时替换为普通 HTTP 请求，两个 API 格式共用传输、超时和失败记录。该路径不再需要智能体子进程、工具禁用清单、桥接事件队列及第二套请求超时。严格拒绝夹带工具调用的文本、截断、多个候选答案和未完成的流。

4 条预先固定的轨迹都在第一个动作前结束：GPT 两条返回 HTTP 401，GLM 两条包含被拒绝的非输出文本流片段。失败全部保留。随后只读检查发现本地路由器未启用原生会话共享；另一次独立 GLM 常量输出诊断成功，但没有复现完整输入的问题。模型列表可见、登录有效、单动作成功，都不能替代实际入口的多轮验收。

2.3 之后采用的验收顺序：先核验目标入口的调用权限 → 用独立诊断记录必要的协议类型元数据 → 通过正反例修复兼容问题 → 发布新的固定多轮验证计划。保留计划、源码提交及失败结果，不能通过重跑、放宽解析规则或悄悄扩大共享认证范围来获得表面成功。

### 阶段 1.8：纠正协议契约，保留剩余失败

**2.4 已交付协议修复；整组真实验收仍未通过。** [独立后续验证](../studies/direct-channel-validation-v2/README.md)删除了三项不必要要求：禁止合法推理片段、强求重复媒体类型、强求最终事件重复已完成的答案。输出项身份、整体完成、单一动作和工具隔离继续保留；本机认证限定在当前客户端请求中。

两种模型各完成一条多阶段任务；另两条在首个动作后分别收到失败/未完成事件或达到固定请求时限。4 条轨迹全部重放，19 次请求中 17 次有完整用量，缺失部分仍未知。新旧任务、接入方式和时限不同，因此不把两轮成功数量的变化解释为因果提升。

**停止用新的私有评分样本调试入口。** 剩余问题用固定规模的公开历史输入和必要的错误类型元数据诊断，不计能力分、不按结果重试。大规模机制实验继续受接入可靠性和目标失败证据约束；阶段 3 的离线测量工作可以独立开展。

## 阶段 2：用最小实验辨认机制——下一研究阶段

**2.2 已实现实验工作流，实证验收仍需证据。** [实验规范](STUDIES.md)固定了等词数中性对照、单项预算提醒、预注册计划、配对交错执行、种子级区间与接入中断的解释边界。[真实模型试跑计划](../studies/verification-reserve-pilot-v1/README.md)在调用前公开；实现工具不等于已经证明机制。

**试跑后的决定：不扩大本实验。** 8 条预定轨迹均已保存并重放。GPT 两种条件均成功；GLM 的两条中性对照分别因非预期工具事件和接入桥超时终止，尚不能解释为预算管理失败。接入桥还遗漏了独立的图像生成开关，因此不能宣称已验证预期的无工具动作通道。两个主要区间均为 [-1,1]。先验证接入能力边界与传输，再审视任务是否有可观察的目标失败。

先研究一个具体问题，例如“单独提醒保留最终验证资源，是否减少预算耗尽导致的交付失败”。

1. 在查看评估结果前，固定假设、主要比较、最小有用效应、模型设置、任务分布、资源预算和停止条件。
2. 只改变一项辅助信息；保持任务、噪声、工具语义和验收标准一致。
3. 先用脚本对照证明目标失败确实能出现，干预能针对该失败；不能区分就先修改实验。
4. 用独立开发样本估计需要多少生成种子；重复调用和语义换皮不当成独立任务。
5. 收集完整配对数据，报告效果、成本、错误类型与种子聚类不确定性。
6. 第一项机制能够辨认后，再增加第二因素及预先规定的交互效应分析。

交付物：小型实验计划规范、版本化干预文本、绑定计划的执行器、明确的主要比较和冻结报告。先不默认展开四因素的全组合实验。

通过标准：对照有效、失败没有被筛掉、多种模型配置和足够独立样本支持解释，且说明是否存在天花板或地板效应。结论只覆盖被检验的干预。

## 阶段 3：引入真正不同的任务结构

先做一个依赖发现环境：探查才能发现局部依赖，行动解锁后续操作，受控变化要求修订计划和恢复。先写观察与转移规范，再写生成器和验收器。

需要：公开信息可执行的成功见证、独立判定器、静态清单/过早停止/拒绝修订/过度探查等失败对照，以及至少一条成功但必须恢复的路径。

通过标准：新增结构确实改变决策，不能靠旧任务换名称满足；按照行动当时的信息区分合理探索和可避免错误。如果仍等价于从已公开的完整列表选答案，就退回诊断任务配置，删除更广泛的能力声明。

**P3.1 已交付离线原型：** [版本化契约](DISCOVERY_RECOVERY.md)只保留一个隐藏依赖、
一个揭示准备操作的探查动作，以及首次验证通过后的一次明确告知的依赖替换。
旧操作、已完成的工作与旧验证同时失效，需要重新发现、重建和验证。
[60 条公开开发轨迹](../studies/discovery-recovery-v1/README.md)全部保留并重放，统一使用 12 点资源、20 步上限。
自适应策略通过四组消融；静态策略在依赖公开且稳定时恢复成功；只发现一次、不修订的策略在移除替换后恢复成功。
过早交付与过度探查始终失败。独立的公开历史验收与状态评分一致。
这只通过了最小契约与对照关卡，尚未完成整个阶段 3，也没有证明模型能力、通用假设发现或真实工作效度。

**P3.2 已在 2.5 实现：** `dependency-cover/1` 加入未知覆盖关系、重叠备选操作、全局执行额度约束和局部失效。
四档结构规模配有公开信息精确搜索、两种较强局部启发式，以及预算／恢复消融，并已接入原有采集与重放路径。
不适用的诊断指标保持空值；批量操作保留资源成本，删除无必要的调用往返。
[192 条开发轨迹与固定模型试跑计划](../studies/coverage-calibration-v1/README.md)区分结构难度证据和真实模型校准。

**下一关（P3.3）：** 实测强模型及不同推理配置的能力边界，随后冻结私有种子与有用的结构留出。
最高档全成功时设计带重叠参照的新版本；失败由接入主导时，先完成公开输入的通道验证，再扩大私有评测。
“更大”不能直接宣称“前沿模型也很难”。不增加领域换皮、并发调度、插件框架或总分。

**当前证据与后续实现：** [第二轮完整实测](../studies/coverage-calibration-v2/README.md)中，
Sol 在一个公开种子上通过了现有最高档；GLM 的对应尝试因响应字节上限中断，不能视为能力失败。
2.5.2 保持默认限额，并提供实验前明确配置的上限及边界测试。
[180 次求解器筛查](../studies/coverage-search-v1/README.md)进一步发现，现有最高档仅需组合 8 个操作，
对精确搜索仍很容易。需要组合 18／24 个操作的新结构目前属于探索候选。
接下来依次验证有界参考求解与恢复消融、冻结候选和结构留出、在明确计算预算下分别比较直接模型与带求解工具的配置。
搜索超过本轮筛查限额本身，不构成晋级正式难度档的理由。

## 阶段 4：检验对真实工作的预测价值

先冻结真实委托任务、外部验收规则和人工介入时间测量，再让基准预测尚未揭晓的真实结果。与静态领域能力及简单成本基线比较，按任务来源留出测试集。

通过标准：在独立任务上提供超出基线的有用预测，或者明确发布负结果并收窄用途。合成环境得分不能代替这项验证。

## 阶段 5：加速和自动化

对已经保留下来的流程度量瓶颈，先消除重复计算；必要时再做并发、公平调度、独立任务族接口和持续评估。每项优化要有前后成本或延迟证据，并保持测量语义不变。

下一步的重点是**P3.3 的真实模型难度校准与固定区分度协议**，在 P3.2 的结构生成和共享证据路径上推进，
对每项难度来源继续执行删除规则。入口诊断作为定额的公开输入检查；2.4 虽有两条完整成功轨迹，整组接入验收仍未通过。
不扩大已完成的试跑，不把执行失败解释为模型机制。协议修复和新合成任务都不能替代机制研究或真实外部效度证据。
