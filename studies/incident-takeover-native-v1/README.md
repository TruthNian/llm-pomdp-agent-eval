# 原生工具调用：独立完整筛选

状态：2026-09-23 已完成。**Sol max 在 9/150 个动作内交付；按预登记规则，淘汰此候选的高难度证据资格。**
先前[文本通道的两次失败](../incident-takeover-v1/README.md)保留，不能当成认知难度证据。

本次通过原生 `exec(target)`、`finish()` 调用控制同一个 PostgreSQL 环境，允许返回普通说明文字，
动作仅取自完整工具调用。镜像、事故、业务目标、观测内容、150 步和业务验收均保持原契约。
适配器版本为 2.14，单次请求 600 秒、整轮 3600 秒，流数据上限在运行前设为 16 MB。
这避免把已观察到的 2 MB 通道容量当作模型推理预算；不是对已完成失败的重判。

[计划](plan.json)规定一次不执行环境动作的 `finish` 协议预检，以及一次 Sol max 完整尝试。
预检失败则不冒称事故测试已运行；不自动重试、不选择性保留结果、不提供事故提示。
原有四个机制对照的复用范围由环境源码哈希和镜像固定，不声称又执行了四组新对照。
完整交付将否定此候选的高难度证据资格；有效决策失败才进入因果审计。

## 实际结果

| 项目 | 观察 |
|---|---|
| 完整尝试 | 1 次，9 次请求、8 次终端调用和 1 次交接 |
| 总耗时 | 325.234588 秒，包含环境准备和终止后验收 |
| 已接受订单 | 110 笔；恢复后、重启后均无缺失或内容变化 |
| 新写入、相同请求重试、冲突请求 | 独立验收全部通过 |
| 中途失败 | 17 次客户读失败、17 次写失败；短时维护在原有契约内允许 |
| 模型动作 | 第 4、5 步命令退出码分别为 3、1，模型自行恢复；无非法协议动作 |
| 适配器 / 观察器 | 均无错误；未人工提示或救场 |
| 报告用量 | 输入 130081、输出 8914、其中推理 4893 tokens；9/9 次有用量 |

第 1–3 步发现进程、普通业务文档、源码、配置、日志和数据库状态。
第 4 步停止 API；`supervisorctl status` 因服务已停止返回非零，触发模型脚本的 `set -e`。
第 5 步有无效 `pg_dump -X` 和 Python 字典集合运算错误。第 6 步自行修正、备份两库、比较业务内容：
alpha 65 笔、beta 54 笔、共同 20 笔；共同记录的业务内容冲突为零。
第 7 步将 beta 独有的 34 笔并入 alpha，重映射内部 ID 和明细外键，统一读写端口并恢复 API。
第 8 步检查业务与持续流量，第 9 步交接。评估者随后独立检查新请求、全部收据及重启持久性。

全部请求的模型名称匹配声明的 `gpt-5.6-sol`，这里只验证路由报告，不证明底层权重身份。
配置、认证和授权文件的采集前后字节未改变。一次完整成功不估计普遍成功率，
但足以触发这次事先规定的候选淘汰规则。短时维护造成的失败请求没有从报告中删掉。

## 设计判断与后续决策

**已观察事实：**稀疏交接没有阻止模型迅速找到双主和读写分离；同一业务引用没有冲突，
两个分支均有完整可查询记录，暂停唯一 API 后可直接比较、备份和合并。
**据此推断：**本候选把恢复压缩成了较短的集合合并问题，未保留来源事故的主要恢复依赖。
这不是通过机制消融建立的普遍因果结论；不能声称扩大数据量或添加组件必然会更难。

保留此案例作为无提示交接、真实数据库操作和原生模型工具接口的回归参照。
不再增加随机种子、记录数量或重复同题来包装高难度。后续实施路径见
[开发路线](../../docs/ROADMAP.zh-CN.md)：从同一个有来源的事故因果链保留真实决策负担，
做一个完整候选后立即筛选，不先扩展题库或重新建设执行平台。
