# 完整传输恢复后的独立 Astra 测试

此前的 [HTTP 502 中断](../stream-delivery-v2/README.md)和
[SSE 提前结束](../stream-delivery-http-retry-v1/README.md)各自封存，没有替换为新成绩。
本次继续使用 GPT-6 Astra `max`，事故、镜像、客户策略与业务验收不变。
2.17.2 将同一个有限重试循环覆盖到明确的服务器错误、连接故障、请求超时与传输提前结束。

[计划](plan.json)在模型调用前冻结：一次独立运行，200 个动作，每次网络尝试
600 秒，整轮 10800 秒，每个逻辑请求最多两次重试。每次重试的输入字节相同，
没有完整有效调用就不执行动作；模型明确返回不完整结果或无效调用不会触发重试。
没有恢复提示、人工救援、降低推理强度或换模型。

真实本地 HTTP 反例验证：SSE 中途结束后的原生调用可按同一输入重试，未完成工具
不会执行；模型明确发出 incomplete 事件则直接失败。连接、超时、预算和 usage
边界也经过检查。它们是工程夹具，实际 provider 结果由本次独立轨迹提供。

本次业务验收通过，但正式交接没有完成：[结果](model-result.md)仍保留为
`execution_interrupted`。模型执行了 17 个动作；第 18 个逻辑请求被解析器以
`unexpected_tool` 拒绝，固定错误描述为“Endpoint streamed an undeclared event type”。
当时没有保留具体事件类型，不能据此断言是哪个事件，也不能把拒绝归因于模型能力。

独立检查确认：交接检查前后及真实重启后，最终 84 个订单、60 笔发货均正确，
12/12 新客户需求得到履行。没有订单、回执或新命令错误，也没有漏发、重复发货、
多余发货或已有发货被修改。105 次后台写失败经普通客户重试恢复，没有成为最终需求遗漏。
客户确认等待值是批次确认的上界，不是逐请求或发货延迟。

两个传输故障触发了已声明的重试，并取得完整有效响应；20 次网络尝试只有 17 份
usage 报告。已报告输入 656,500 token、输出 14,736 token，合计 671,236；未报告的
请求费用和缓存用量未知，不能把这部分计为零。整轮耗时 1,052.621216 秒，包含环境
准备、运行和独立验收。没有把最后一个无效响应转换为 finish，也没有追加人工动作。

[完整证据](evidence.json.gz)、[轨迹](trajectories.html.gz)与
[文件封存](execution.json)可由 `python studies/stream-delivery-transport-retry-v1/evidence.py verify`
重新核验。这条轨迹证明了该模型在这一个事故中恢复业务的实际表现；没有证明正式
交接成功、模型总体成功率或前沿模型难度。这三个同一事故运行不合并估计总体能力。
