# 正常 HTTP 重试后的独立 Astra 测试

前一次 `stream-recovery/2` 测试因上游 HTTP 502 中断，
[原始结果](../stream-delivery-v2/README.md)已单独封存，没有改判。
本次使用同一事故、镜像、客户需求及业务验收，仍为 GPT-6 Astra `max`；
只在 2.17.1 的既有 HTTP 适配器上明确启用最多两次服务器错误重试。
没有新服务、新故障、降低推理强度或更换模型。

[计划](plan.json)在模型调用前冻结。一次完整独立测试，200 个动作，
每次网络尝试 600 秒，整轮 10800 秒。仅 500/502/503/504 允许按相同输入重试，
环境在等待期间继续运行，全部网络尝试及未报告 usage 均保留。
这是普通客户端传输行为，不是整轮失败后的隐蔽补考。

本次在 `aa09ad0` 的干净源码上执行并结束。第 7 次请求的 HTTP 响应已成功，
但 SSE 在完整响应到达前结束，未执行该次工具动作，因此记为**接入中断**。
该请求没有出现 HTTP 5xx，所以本版只针对服务器状态码的重试未被触发。
不能把这次中断解释成 Astra 的认知失败，也不能声称本次验证了线上 502 恢复。

已报告输入 112,302、输出 1,560，总计 113,862 token，覆盖 6/7 次请求。
第 7 次没有 usage；实际总消耗、缓存分项和费用未知。中断后独立观察的业务状态
仍不完整，重启后有 26 个订单状态错误、38 笔缺失发货，新客户实际需求完成 6/12。
它们是中断时的后果，不是模型主动交接后的终局能力成绩。
